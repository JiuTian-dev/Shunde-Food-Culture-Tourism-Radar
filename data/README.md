## 二、字段约定

统一 Schema：`id / sampleType / name / category / district / address / operating / owner(主理人) / craft(工艺) / reputation(口碑) / pricingCapacity(价格产能) / potentials(五维预评分) / risks(风险) / evidence(来源证据) / createdAt`。

正样本额外含 `lifetime`（爆前→引爆→峰值→退潮时间线）。

## 三、爆款指数公式

```
爆款指数 = 0.25×人设反差度 + 0.25×风味品相度 + 0.20×故事叙事性 + 0.20×情绪共鸣度 + 0.10×素材续航度
```

- **风险是门槛因子**：命中高风险项 → 一票降级（如"产能极低"标注"需先扶持再引爆"；卫生/资质问题 → 不推荐）。
- 评分标准见模板第三节 rubric。

## 四、与 Agent 工作流接口约定

| Agent | 读取 | 用途 |
|---|---|---|
| ① 声呐哨兵 | 全部 | 提供候选池来源（本数据集即声呐产出） |
| ② 故事矿工 | 全部 owner/craft | 提取故事素材卡 |
| ③ 诊断医师 | candidates + negative | 用 `potentials` 预评分做校验基准，输出诊断报告 |
| ④ 流量预言师 | positive 的 `lifetime` | 以莫氏等标答校准预测模型 |
| ⑤ 文旅总策划 | 全部 | 生成培育方案 |

## 五、预评分说明

`candidates.yaml` 的 `potentials` 为**人工预评分**（基于公开信息），不是最终值——它是给诊断 Agent 的对标基准，诊断 Agent 需独立判断并给出理由，可校正预评分。

## 六、构建与合规规范

1. 只用公开可溯源信息，`evidence` 必填（来源+URL+日期）。
2. 信息不足的字段标注 `待核`，**不编造**。
3. 负面信息只记录公开报道事实。
4. 莫氏鸡煲为"圣杯标答"，`lifetime` 必须最完整。
