# 顺德美食潜力数据集 · 数据模板 v1

> 用途：为「顺德美食流量孵化引擎」的 AI Agent 矩阵提供结构化的"潜力店情报"数据底座。
> 目标规模：30~40 家（正 3~5 / 反 5~8 / 候选 20~25）。
> 版本：v1 · 日期：2026-08-14

---

## 一、样本分层

| sampleType | 含义 | 数量建议 | 数据采集深度 |
|---|---|---|---|
| `positive` | 已验证走红（爆款标答），用于校准预测模型 | 3~5 家 | 最深，必须含 `lifetime` 全生命周期 |
| `negative` | 有名气/有传统但没爆，教模型分辨"该爆 vs 不该爆" | 5~8 家 | 中 |
| `candidate` | 有潜力但还没大爆，Demo 主角，用于展示全链路 | 20~25 家 | 满足诊断字段即可 |

| `story` | string | ✅ | 人生叙事/坚持/传承故事 |

### 工艺对象 `craft`
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `keywords` | string[] | ✅ | 工艺关键词（现宰/手作/祖传/非遗…） |

### 口碑对象 `reputation`
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `score` | number | ✅ | 口碑分（1-5） |
| `reviewKeywords` | string[] | ❌ | 评价词云 |
| `regularCustomers` | string | ✅ | 核心客群（街坊/游客/老饕…） |
| `buzz` | string | ✅ | 当前网络声量现状 |

### 价格与产能 `pricingCapacity`
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `priceBand` | string | ✅ | 价格带/人均 |
| `capacity` | string | ✅ | 接待能力（现在 & 上限） |
| `limit` | string | ❌ | 限号/限量机制 |

### 爆款潜质五维 `potentials`（0-100）
`人设反差度` / `风味品相度` / `故事叙事性` / `情绪共鸣度` / `素材续航度` —— 评分标准见第三节 rubric。

### 风险 `risks`
`string[]`，可能包含：产能不足 / 卫生资质 / 价格争议 / 老板上镜意愿 / 人设崩塌隐患 / 供应链依赖。

### 生命周期 `lifetime`（**仅 positive**）
`[{ date, event, metrics }]` —— 记录爆前→引爆→峰值→退潮完整时间线，是预测模型校准的"标答"。

### 来源证据 `evidence`
`[{ source, url, date }]` —— **每条数据必须可溯源**。

### 元信息 `createdAt`
构建日期。

## 三、爆款潜质评分体系（rubric，防止拍脑袋）

> 爆款指数 = `0.25×人设反差 + 0.25×风味品相 + 0.20×故事叙事 + 0.20×情绪共鸣 + 0.10×素材续航`
> **风险是门槛因子**：命中高风险项 → 一票降级（如"产能极低"标注"需先扶持再引爆"；卫生/资质问题 → 直接不推荐）。

| 维度 | 权重 | 90+（顶级） | 70+ | 50+ | <50 |
|---|---|---|---|---|---|
| 人设反差度 | 25% | 有"劝退/自黑/金句"级反差 | 性格鲜明有记忆点 | 有辨识度但无梗 | 普通店主，不表达 |
| 风味品相度 | 25% | 现宰/非遗/手作+强出片 | 地道风味，画面尚可 | 出品稳定但无视觉冲击 | 标准化/工业化 |
| 故事叙事性 | 20% | 有完整人生弧光（还债/坚守/翻身） | 有可讲的传承/坚持 | 有背景但挖不深 | 无故事 |
| 情绪共鸣度 | 20% | 原生真诚，击中时代情绪（治愈/乡愁/奋斗） | 有烟火气/人情味 | 一般好感 | 无共鸣点 |
| 素材续航度 | 10% | 可无限产出不同内容 | 可拍20+条 | 可拍5-10条 | 一两次就枯竭 |

## 五、构建与合规规范

1. **只用公开可溯源信息**：每条数据带 `evidence`（来源+URL+日期），禁止编造。
2. **不采集私人信息**：主理人信息只用公开报道内容。
3. **负面信息只记录已公开报道的事实**（如卫生记录、价格争议），不主观造谣。
4. **莫氏是全套"标答"**：lifetime 必须完整，预测模型以此校准。
5. **构建顺序**：先建 3 正（含莫氏全生命周期）→ 再建 5~8 反 → 再铺 20~25 候选。
